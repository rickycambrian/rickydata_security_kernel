# RickyData Security Evidence

`latest.json` is the current machine-readable proof bundle for production TEE security posture. It is generated by the private `knowledgeflow_db` CI/CD workflow and published here so users can audit the evidence without access to the private monorepo.

## What It Proves

- The live KFDB TEE endpoint is healthy.
- The live endpoint reports TPM PCR-bound key release (`key_source=tpm_pcr`).
- The live endpoint is running in enforced release-guard mode.
- The deployed image digest and public security-kernel source hash are present in the live verification endpoint.
- The attestation challenge endpoint signs a fresh client nonce.
- The S2D canary stores user-keyed ciphertext at rest when enabled.
- A stopped-when-idle GCP Confidential VM lab can boot as SEV-SNP and complete a TPM PCR policy seal/unseal round trip.

## What It Does Not Prove

- It does not reveal or publish private monorepo source code.
- It does not prove Google hypervisor-host memory extraction resistance via `vmgrab`; that requires a separate owned KVM/Kata-SNP lab where the test runner controls the host.
- It does not make this source-available package a complete byte-for-byte copy of the private production runtime. The evidence binds the public audit surface to the deployed image digest and runtime verification endpoints.

## Files

- `latest.json` - current evidence bundle.
- `runs/*.json` - timestamped historical evidence bundles.
- `schema.json` - JSON schema for the evidence bundle shape.

## Verify

```bash
curl -s https://tee.knowledgeflowdb.org/health | jq '.security_posture'
curl -s https://tee.knowledgeflowdb.org/api/v1/security/verify | jq .
```

The public bundle should match the live endpoint's image digest, security-kernel hash, and key posture.
